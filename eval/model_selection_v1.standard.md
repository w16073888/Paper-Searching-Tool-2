# model-selection-v1 判定标准

## 1. 用途

比较 `qwen3-8b`、`qwen3-14b` 与可选的移动云
`deepseek-v4-flash-0731` 在固定问题上的知识、比较、项目约束和 OOD 行为。

该集合不是项目端到端主回归，也不替代 `v2_acceptance_16.json`。它只回答
“在相同提示下，候选模型的答案覆盖和约束遵循是否不同”。

## 2. 冻结要求

- 首次模型运行后不得修改题目、参考答案、关键词组或长度上限。
- 不根据模型输出调整 prompt，不删除失败题，不给某个模型追加提示。
- 每道题只以 `temperature=0`、`top_p=1` 运行一次。
- 三个模型必须使用相同的系统提示和 `max_tokens`。
- 原始输出、usage、延迟和自动判定全部保留。

## 3. 自动判定

每题通过必须同时满足：

1. `must_include` 每个关键词组至少命中一个替代词。
2. 是否拒答与 `expected_refusal` 一致。
3. 输出长度不超过 `max_chars`。

关键词匹配会把英文转成小写并压缩空白。自动判定只用于可复现筛查；
若两个模型分数接近，再对原始答案做人工盲评。

## 4. 分流规则

- 8B 与 14B 显存条件不同，性能只比较各自稳定运行的配置。
- 公平性能测试另用相同上下文长度、单序列、eager、关闭 prefix cache。
- 移动云 API 是异模型外部对照，不用于推断 8B/14B 模型规模效应。

## 5. 判定门槛

14B 只有在以下条件同时满足时才建议替换 8B：

- 本集合通过数至少比 8B 高 2 题，即绝对提升至少 `2/24 = 8.3%`。
- `project_contract` 与 `out_of_scope` 不出现比 8B 更差的题。
- 16 题项目端到端回归不低于 8B。
- 性能和稳定性满足 `model-benchmark-v1` 的部署门槛。

若本集合打平或提升不足，不因模型参数更多而替换 8B。
