# 算法亮点实施优先级：主题图谱与可视化 > 证据覆盖 Agent > 热点统计校准

> 撰写：2026-10-30。用户拍板的长期优先级，不是当天流水账。
>
> 编号沿用 2026-10-30 对话中的候选表：
> 2 = 主题演化/语义图谱；3 = 证据覆盖驱动的 Agent；1 = 跨会扩散的统计校准。

## 1. 决策摘要

| 优先级 | 方向 | 为什么排在这里 | 当前结论 |
|---|---|---|---|
| P1 | **主题演化/语义图谱与可视化** | 用户心中优先级最高；能最快把现有 220 簇、质心、关键词和年份/会议分布转化成可观察、可解释的产品差异 | **先做** |
| P2 | **证据细化与证据覆盖驱动 Agent** | 决定回答是否可信、是否真的“不是套壳”，但会改 Agent 状态机，放在图谱稳定后做 | **第二做** |
| P3 | **跨会扩散统计校准** | 直接强化“热点”核心命题，但研究性和离线返工最重；用户接受后置 | **第三做，仍不可砍** |

执行顺序固定为：

```text
主题图数据 → 图算法 → 可视化
→ EvidenceState/覆盖度 → 受控工具选择
→ venue/year 统计校准 → 置信度与排序
```

先做可视化不等于只改前端。必须先生成真实、可复现的主题图数据，再由前端展示，不能用装饰性连线代替算法。

## 2. 共同约束

- 对外接口只增不改；新增字段必须有默认值，前端仍只依赖 `hotspot.api`。
- topic snapshot 和 topic graph 分别版本化；新算法不得静默改变旧快照语义。
- 继续遵守三态红线：对外只使用 `铺开 / 新进 / 单会`，不得输出“退潮 / 下降 / 衰退”。
- 主题图只能称“语义邻近 / 主题关联”，不得暗示引用、影响或因果。
- 热点统计暂不全量重做前，现有 `spread_state` 只作描述，不新增“置信热点”宣传。
- 不使用已退役的 `v2_comparison_holdout_v1` 调优或复跑；算法改动另建 v2 holdout。
- 第一轮不训练 RL、不做多智能体、不引入图数据库或大模型微调。

## 3. P1：主题演化/语义图谱与可视化

### 3.1 目标

把现有“查到一个主题簇”升级为：

```text
查询 → 种子主题 → 语义邻域 → 相关子主题 → 年份/会议轨迹
```

用户应能在一个视图中回答：

- 这个问题属于哪些主题？
- 哪些主题与它语义相邻？
- 相邻关系是关键词、论文向量还是会议/年份分布造成的？
- 该主题在 2024/2025 的簇边界和覆盖状态是否稳定？

### 3.2 算法

1. 以 220 个主题簇为节点。
2. 使用快照已有字段构造边权：

```text
edge_weight =
    0.55 * centroid_cosine
  + 0.25 * top_term_jaccard
  + 0.10 * venue_profile_similarity
  + 0.10 * year_profile_similarity
```

3. 每个节点只保留 Top-K 邻居，初始 `K=8`，删除弱边。
4. 查询先用现有 `TopicStore.search()` 找 2–3 个种子簇。
5. 在主题图上做 Personalized PageRank：

```text
r(t+1) = alpha * P^T * r(t) + (1 - alpha) * seed_vector
```

6. 最终排序：

```text
final_score = 0.60 * query_similarity + 0.40 * ppr_score
```

7. 用 Hungarian matching 对齐同一主题簇内的 2024/2025 子质心，生成主题轨迹；只展示存在或增强的关系，不输出衰退结论。

### 3.3 交付物

- `hotspot/structure/topic_graph.py`
  - 构图、裁剪 Top-K、归一化邻接矩阵、Personalized PageRank。
- `scripts/build_topic_graph.py`
  - 从生产 topic snapshot 构建版本化主题图。
- `hotspot/data/topic_graph_v1.json.gz`
  - 保存节点属性、边、布局坐标、构建参数和来源快照哈希。
- `TopicStore` 的只读图查询 adapter。
- 新增 Agent 工具 `get_topic_neighbors(cluster_id, limit)`。
- API 新增带默认值的 `topic_graph` 字段；不直接改写旧 `graph` 语义。
- 前端展示：
  - 查询种子节点；
  - 语义邻居；
  - 边权/关系类型；
  - 2024→2025 主题轨迹；
  - 点击节点返回代表论文和会议/年份计数。

### 3.4 展示原则

- 默认只展开查询命中的 Top-3 种子及其一跳邻居，避免 220 节点“毛线球”。
- 节点大小表示簇规模，颜色表示铺开/新进/单会，线型区分语义、关键词、会议/年份邻近。
- 图必须配表格：`主题 / 规模 / 代表词 / 会议分布 / 年份分布 / 邻接理由`。
- 先保证可解释，再考虑动画和复杂布局。

### 3.5 验收

- [ ] 每个主题至少有 1 个、至多 8 个可解释邻居。
- [ ] 30 条查询人工检查：种子主题相关，邻域不是纯关键词噪声。
- [ ] 同一快照和参数重复构图，边集合完全一致。
- [ ] 图查询 P95 额外延迟不超过 200 ms。
- [ ] 不改变现有 `meta` / `ask` 必填字段。
- [ ] `g01–g20`、验收 16 题无路由或引用回归。

## 4. P2：证据细化与证据覆盖驱动 Agent

### 4.1 目标

把当前“LLM 自由调用 search/fetch/topic”改成：

```text
显式证据状态 → 判断缺什么 → 选择边际收益最高的动作 → 足够后停止
```

LLM 仍可生成检索词和最终 claim，但预算、停止条件和比较题双侧证据由控制器机械约束。

### 4.2 数据结构

新增请求级 `EvidenceState`，至少包含：

```text
intent                 fact / trend / compare / relation
required_aspects       任务、方法、数据、结论、限制、比较对象等
covered_aspects        已由 fetched 摘要覆盖的方面
candidate_clusters     已命中的主题簇
fetched_papers         已取得摘要的论文
compare_sides          两侧各自的证据数
venue_coverage         已覆盖会议
year_coverage          已覆盖年份
duplicate_actions      重复 action 次数
```

### 4.3 动作收益

第一版使用确定性的边际覆盖分数，不训练策略模型：

```text
utility(action) =
    0.40 * 新增方面数
  + 0.25 * 新增主题簇数
  + 0.20 * 比较两侧平衡增益
  + 0.10 * 新增高相关证据数
  - 0.10 * 调用成本
  - 0.05 * 重复风险
```

动作空间保持小：

```text
search_papers
fetch_papers
get_topic_overview
get_topic_neighbors
stop_and_answer
```

### 4.4 分意图停止条件

| 意图 | 最低证据条件 |
|---|---|
| fact | 至少 1–3 篇直接相关摘要，且关键方面被封住 |
| trend | 有主题证据；若引用多个主题，必须有会议/年份计数支撑 |
| compare | 两侧各自达到最低论文数，且双侧证据量大致平衡 |
| relation | 两侧主题均存在；只能基于论文摘要/主题图陈述，缺图证据时明确限制 |
| refuse | scope 判为域外，或候选证据不足且扩展一次后仍无新增 |

通用停止条件：

- 所有必需方面已覆盖；
- 下一动作的预计新增证据低于阈值；
- search/fetch 预算耗尽；
- 连续动作只返回重复 ID。

### 4.5 Trace 与证据细化

每个 action 记录：

```text
intent
action
coverage_before
coverage_after
new_ids
duplicate_ids
action_utility
stop_reason
```

回答中的 claim 后续可继续细化为：

```text
claim -> evidence paper_id -> evidence span -> support status
```

第一轮先做 paper/abstract 级覆盖；evidence span 与 NLI 校验作为后续增强，不与控制器首版同时上线。

### 4.6 交付物

- `hotspot/agent/coverage.py`
  - 方面抽取、覆盖更新、动作收益、停止条件。
- `AgentDeps` 增加 `EvidenceState`、`intent` 和 coverage 缓存。
- `search_tool` / `fetch_tool` 返回后更新状态。
- Agent prompt 增加“当前缺少什么证据”，但预算与 action mask 由代码控制。
- Trace 增加覆盖前后快照。
- 新增固定 fixture：
  - 比较题缺一侧时不允许停止；
  - 重复搜索收益为 0；
  - 事实题证据充足时应停止；
  - 扩展后仍然重复时安全拒答。

### 4.7 验收

- [ ] 比较题双侧证据覆盖率提升。
- [ ] 重复工具调用率下降。
- [ ] 证据完整率在固定问题集上提升，且人工抽检可解释。
- [ ] P95 总延迟不明显恶化，目标不超过现有 30 秒量级。
- [ ] 验收 16 题、`g01–g20` 不回归。
- [ ] 新增 evidence trace 可回放下一次动作选择。

## 5. P3：跨会扩散的统计校准

### 5.1 目标

保留三态名称，但把“为什么是铺开/新进”从人工规则升级为可检验统计：

```text
会议规模校正 + 置换显著性 + 聚类稳定性
```

### 5.2 算法

1. 按 `year × venue × cluster` 统计：

```text
p(c, v, y) = papers(c, v, y) / papers(v, y)
```

2. 每个会议年份设置最低证据量 `m`，例如至少 2–3 篇。
3. 固定主题成员，在同一 `year` 内置换论文的 `venue` 标签，保持各会议论文总数不变。
4. 重复 1000 次，得到广度零分布。
5. 计算：

```text
breadth_z
p_value
Benjamini-Hochberg q_value
diffusion_score
```

6. 另用多 seed/80% 抽样重复聚类，计算主题成员 ARI 或 Jaccard，作为 `stability`。
7. 状态判定仍只输出三态；增加“高/中/低置信”展示层，不增加第四态。
8. 2024/2025 不得混成一个会议计数；每年单独计算，当前展示年份需明确。

### 5.3 排序

趋势主题排序可改为：

```text
rank_score =
    query_similarity
  * diffusion_effect
  * stability
  * log1p(support)
```

不将 `p_value` 直接作为排序分数，避免极小样本或海量主题造成误导。

### 5.4 交付物

- `hotspot/structure/topic_stats.py`
- `scripts/build_topic_snapshot.py` 增加统计阶段。
- `topic_snapshot` schema v2；`TopicStore` 兼容 v1/v2。
- `TopicHit` 增加带默认值的：
  - `diffusion_score`
  - `breadth_z`
  - `breadth_q`
  - `stability`
  - `support`
  - `edition_year`
- `meta` 暴露统计口径版本。

### 5.5 验收

- [ ] 合成数据中“均匀跨会”显著，“单会堆满”不显著。
- [ ] 多重检验校正后没有大批主题虚假显著。
- [ ] 重复构建统计结果一致。
- [ ] 高置信主题人工可读，低稳定主题被降权或明确标注。
- [ ] 三态标签仍只有三种，且不出现衰退类表述。
- [ ] 趋势题与验收题完成新版本 holdout 复核。

## 6. 暂不做

- 不用多智能体 swarm 代替显式状态机。
- 不在 Trace 数量不足时训练 RL / contextual bandit。
- 不为“图谱感”引入 Neo4j；220 节点用 NumPy/igraph 足够。
- 不把主题语义邻近包装成引用网络或学术影响。
- 不在统计校准完成前新增“热点强度排行榜”。
- 不为可视化直接写死前端假数据。

## 7. 阶段门禁

| 阶段 | 进入下一阶段前必须满足 |
|---|---|
| P1 主题图 | 图构建可复现、查询图延迟可控、API additive、现有问答不回归 |
| P2 证据控制 | fixture 通过、双侧/重复/停止条件稳定、Trace 可回放 |
| P3 统计校准 | 置换检验与稳定性可复现、三态语义不变、新 holdout 通过 |
