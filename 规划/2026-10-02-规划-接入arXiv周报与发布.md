# 接入 arXiv 周报 & 集中向量化发布 · 规划

> 定位：把本项目的**检索 / 聚类 / 热点判定规则**接到 `D:\大学编程学习\arXiv周报` 的连续流上
> （每周处理新内容 + 检索累积老库），并让**别人以极低代价**检索周报与老库、且每周能检索到更新。
> 时间：2026-10-02 拟定。配置口径见 `2026-09-21-热点挖掘系统-方案设计.md`；周报侧边界见 `D:\大学编程学习\arXiv周报\README.md`。

---

## 1. 目标（用户原话复述）

1. **接入周报**：把检索规则应用于 arXiv 周报——既处理**每周新增**内容（增量），又能**检索老库**。
2. **对外可用 + 可持续更新**：别人用**尽量少的代价**检索周报和老库；**我每周更新周报，别人也能检索到最新**。

## 2. ★ 关键决策（2026-10-02 用户拍板）

| 决策 | 选项 | 拍板 |
|---|---|---|
| 分享形态 | 本地网页 + 内网穿透 | **② 本地 `Streamlit` 服务 + frp/ngrok**（别人只开浏览器，零安装） |
| 数据组织 | 独立源 vs 并入 | **独立 `arXivCorpus`、与会议库并列、共享同一套引擎**（不污染跨会语义） |
| 向量检索负担 | 别人端是否要装 embedding 模型 | **不**——**向量化集中做一次，发布已向量化的产物**，别人端用轻量余弦检索消费 |

> **核心设计**：把「向量化」这个最贵/最吃算力的步骤**收敛到你侧、每周只做一次**，发布**已向量化的产物**；
> 别人拿到 `向量 + 元数据` 即可检索，**不下载 embedding 模型、不装重型依赖**。
> 这把「别人少代价」和「每周更新别人可检索」彻底解耦。

---

## 3. 数据兼容性（为什么接入成本低）

周报 `数据/papers.jsonl`（arXiv 三分类连续流，append-only，2026-09 已 ~4369 行）字段与
本项目 `hotspot/corpus.py::MergedCorpus._load_source` 契约**基本兼容**：

| 本工程 `Paper` 字段 | 周报 `papers.jsonl` 字段 | 兼容 |
|---|---|---|
| `paper_id` | `paper_id`（`arxiv:xxxx`） | ✅ |
| `title` / `abstract` | 同名 | ✅ |
| `year` | `year`（论文自定义年份） | ✅ |
| `arxiv_id` | `arxiv_id` / `source_key` | ✅ |
| `is_rl` / `subfields` | `rl.is_rl` / `rl.subfield` | ✅ |
| — | `topics`（cs.LG/stat.ML/cs.AI） | 周报多出的**分类轴** |
| — | `first_seen` / `last_updated` | 周报多出的**时间轴**（增量判定现成） |

**关键差异（决定热点语义怎么改）**：

| | 会议库 | 周报 |
|---|---|---|
| `venue` | 会议名（4 个） | **恒为 `"arXiv"`** |
| 更新 | 静止 | 每周 append（日更） |
| 热点轴 | 跨会（跨 4 会）三态 | **无「会」** → 需换成「分类」或「周」 |

## 4. 引擎层方案（独立 arXiv 源，共享引擎）

### 4.1 数据源
- 新增 `arXivCorpus`：复用 `MergedCorpus` 的读取/查询接口作为薄适配器，读周报 `数据/papers.jsonl`；
  与会议库并列、不合并（`config.yaml` 的 `corpus.sources` 加一份或独立字段）。前端可切换数据源。
- 🟠 建议在周报侧定义一个**只读接口**，避免两库各自复制 loader。

### 4.2 热点轴切换（⚠️ 需拍板，见 §7 未决）
会议「跨会」三态在 arXiv 上无对应，候选轴：
- **轴 A（按 arXiv top-level 分类）**：cs.LG / stat.ML / cs.AI 充当「会」→ 铺开 = 出现在 ≥2 分类，新进 = 只出现在末位新分类，单会 = 其余。
  缺点：分类仅 3 个且语义交叉少。
- **轴 B（按周时间批次）**：用 `first_seen` 的周做「本周新增 vs 已在库」→ 判定"本周新进方向"。
- **推荐**：**轴 B（周窗口）做「本周新增」判定 + 轴 A（分类）做辅助聚合**。⚠️ **无论哪轴，输出仍是三态（铺开 / 新进 / 单会），不输出「退潮 / 下降 / 衰退」（红线保留）**。

### 4.3 检索
- 词级检索：复用 `MergedCorpus.search`（零模型负担）。
- 向量检索：复用 `hotspot/retrieval/vector.py` / `rlr.py`（mmap 省内存）——**向量由你侧集中生成，见 §5**。

### 4.4 增量向量化
- 每周日更后，对**新增 `paper_id`**（相对上次向量化集合）跑 embedding（复用 `hotspot/structure/embed.py`）；
  **断点续跑**（按已向量化 id 集合跳过），累积到向量库。
- 不重算老论文（若 embedding 模型更换，需全量重建——记录模型版本到 `manifest`）。

## 5. 发布层方案（集中向量化 → 发布已向量化产物）

### 5.1 发布物格式（别人拿到即能检索的一包）
```
weekly_arxiv/
  vectors.npy        # 稠密向量矩阵（行序 = ids 序）；或 FAISS index
  ids.jsonl          # 与向量行对齐的 paper_id 序
  meta.jsonl         # 标题/摘要/arxiv_id/topics/first_seen/week
  topics.json        # 热点规则输出（本周新进 / 铺开簇，三态）
  manifest.json      # embedding 模型版本、覆盖到哪周、论文数、构建时间、sha256
```
> **检索不依赖 LLM**：别人端纯 `numpy` 余弦 top-k + 摘要展示 = 零 API、零模型。LLM 版（带引用叙述/verify）只在**你侧的网页/服务**里跑。

### 5.2 别人侧两档使用
- **网页（推荐）**：本机 `Streamlit`（复用 `hotspot/ui/app.py`，加数据源切换 + 本周新增标注）+ **frp/ngrok 内网穿透** → 别人浏览器直达，检索周报和老库。
- **轻量发布物包**：别人下载上面 `weekly_arxiv/` 包，自行跑一个纯 numpy 检索脚本（<100 行）。

### 5.3 每周更新闭环（一条命令，增量幂等，可挂 `automation` / 任务计划）

> **核心：只处理「本周新增」，不折腾历史**（2026-10-03 用户拍板）。
> 首次 `python scripts/update_arxiv_weekly.py --init` 建立水位基线=当前全库（跳过历史），
> 之后每次日更/周更后跑一次即增量入库 + 更新发布物：

```
arXiv 日更（周报已有）→ python scripts/update_arxiv_weekly.py
   ① 水位检测新增（watermark.json 对比 paper_id）
   ② 只对新增 embedding → arxiv_vectors/vec_delta_*.npz（历史分片不碰）
   ③ 只对新增拉 S2 引用 → 并入 cite_graph_arxiv.pkl（only=新增）
   ④ 重新打包发布物 weekly_arxiv/（新增自动并入 vectors/meta/topics/manifest）
   ⑤ 水位前移 = 当前全集
   → 上传 / 更新穿透机网页数据 → 别人检索到的即最新
```

## 6. 分阶段实施（可落地顺序）

| 阶段 | 内容 | 产出 / 验收 |
|---|---|---|
| **P1** | `arXivCorpus` 读取 + 前端数据源切换 + 词级检索跑通 + 「本周新增」标注 | 前端可切到周报，能搜到上周新论文 |
| **P2** | 增量向量化管线（断点续跑）+ 累积向量库 + 向量检索 | 周报也支持向量检索 |
| **P3** | 发布物生成（npy/meta/topics/manifest）+ 上传机制 | 每周产出一包可下载的已向量化库 |
| **P4** | 网页服务 + 内网穿透 + 每周自动化脚本 | 别人浏览器可用，我每周自动更新 |

## 7. 未决 / 风险

- **热点轴口径待拍板**：轴 A（分类）vs 轴 B（周窗口），及三态在 arXiv 上的精确判据（见 §4.2）。
- **向量化模型选择**：bge / sentence-transformers 哪一档（精度 vs 单次成本 vs 别人端尺寸无关）。影响 P2。
- **发布存储位**：对象存储 / 云盘 / 穿透机本地——决定"别人怎么拿到发布物"。
- **别人端网页的 LLM 依赖**：网页若跑验证/叙述需服务端 API key → 都在你侧，别人零 API（确认无泄漏）。
- **两库 git 边界**：周报在独立库 `D:\大学编程学习\arXiv周报`（数据不并入移动云杯 git）；repo 只读，不写周报侧一个字。

## 8. 引用图增强暂缓（2026-10-22）

arXiv 的 `relation` / MPS / 周报 RF 需要额外引用图与训练数据，不属于当前
agent/工具重建主线。2026-10-02 已确认 Semantic Scholar 无 key 时 429 频繁，
OpenAlex 对 arXiv 引用支持不足；没有可用引用源时诚实降级，不阻塞基础周报检索。
未来恢复该方向时，从 Git 历史恢复已删除的专项设计，或重新评估引用数据源。

## 9. 云端日更与周封卷落地（2026-10-25）

### 9.1 周绑定口径

- 论文成员只由 `first_seen` 的 ISO 周决定，发布周与首次出现周分离。
- `replace` / `cross` 等公告只写入 `announcements.jsonl`，不把老论文搬到新周。
- 每周产物固定为 `member_papers.jsonl`、`announcements.jsonl`、
  `harness_input.jsonl`、`manifest.json`，LLM harness 使用 `weekly-harness-v1`。
- 历史缺失日保持 `partial`；当前 RSS 无法回补过去日批次，禁止伪造。

### 9.2 流水线

`scripts/daily_arxiv_sync.py` 串起 vendored 抓取器、周绑定、缺失向量增量化和
arXiv LanceDB 重建。文件锁避免 cron 重入，同日完整运行幂等跳过；受限冒烟批次不得
作为正式 `.done`。

封卷使用 `--seal-week`，只发布、不再抓取。周一至周五五个 `.done` 必须全部有效，
失败 feed、停滞 feed、旧 feed、`limit` 或 `license-limit` 任一出现都拒绝封卷。

### 9.3 云端调度

服务器时区为 UTC，用户级 cron 使用：

```text
30 5 * * 1-5  run_weekly_cron.sh
0 13 * * 0  run_weekly_cron.sh --seal-week
```

即上海时间工作日 13:30 日更、周日 21:00 封卷。日志分别写
`data/arxiv-weekly/state/cron-daily.log` 与 `cron-seal.log`。

### 9.4 验收口径

- `python scripts/check_weekly_pipeline.py` 必须为 `7/7`。
- 周检索必须显式带 `scope.week_id`，结果逐条检查 `week_id` / `first_seen`。
- 新增论文必须补齐向量后再重建 arXiv 索引；索引 manifest 的 `papers` 应等于
  周报 `papers.jsonl` 可索引论文总数。
- 首轮正式日更后核对 `.done`、当周 harness、向量分片、LanceDB 计数和服务检索。
